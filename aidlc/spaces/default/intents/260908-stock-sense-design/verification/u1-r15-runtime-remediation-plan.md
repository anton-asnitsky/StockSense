## Candidate construction

1. Freeze the three base/head/test-merge tuples, image IDs, raw inventory and baseline consumer manifests separately. Preserve unrelated work and existing validator repairs. Re-resolve the .NET 10 Noble chiseled-extra tag to its **amd64 child manifest** in isolation. Examine its authenticated package identities. The old child `sha256:e7e90bfc3ce16f9efdf18c25c7e4876af4ffba7ea50582878f6ea05b1e04a7ec` contains libc6 2.39-0ubuntu8.9. A candidate needs libc6 2.39-0ubuntu8.12 or a later Ubuntu release demonstrably fixing all six matches, plus a supported .NET payload.
2. If the publisher image fails this test, use a fixed snapshot of Noble release, updates and security for a clean chiseled rootfs. Start by testing `20261116T000000Z`; Canonical's publication API lists amd64 libc6 2.39-0ubuntu8.12 in Security and Updates on November 12. The publication record establishes availability, not a verified snapshot or complete image. Verify Ubuntu archive signatures, index checksums, dependency closure, exact binary/source versions and each deb SHA-256. Pin builder manifest, archive key identity, Chisel binary checksum, slice definitions and wrapper commits. Fail the build if a required input is missing, mutable or fetched outside the selected snapshot. [Ubuntu publication API](https://api.launchpad.net/1.0/ubuntu/+archive/primary?ws.op=getPublishedBinaries&binary_name=libc6&exact_match=true&distro_arch_series=https://api.launchpad.net/1.0/ubuntu/noble/amd64&status=Published) · [Ubuntu snapshot service](https://snapshot.ubuntu.com/)
3. Reproduce Microsoft's Noble extra runtime slice set including loader, native runtime libraries, certificate roots, ICU, timezone data, OS identity and generated package/file inventory. Construct a new final filesystem with the authenticated .NET runtime and host from the pinned Microsoft payload; verify payload hashes, loader resolution and host discovery. Keep the builder, SDK, package tools and build secrets out of the final filesystem. The release recipe must rebuild the complete final image from reviewed immutable inputs. Retain the stage digests, package lock and generated Chisel/dpkg manifests so a reviewer can reproduce the inventory. If the new rootfs cannot meet the same behavioral and supply-chain checks, stop and report the failed check. [Microsoft chiseled image guidance](https://github.com/dotnet/dotnet-docker/blob/main/documentation/ubuntu-chiseled.md)
4. Keep Kiota 1.38.0 and its approved nupkg SHA-256 `ec934c391c94e156543ce63cb497d6944180105b2b794b8b3a53a89b89cd4d82`. Retain the approved SDK pin. On #74 apply the already reviewed 1.38.0 host and image tool alignment, then regenerate that story's profile and manifest. On #75 and #76 preserve each branch's generation inputs and C18 fixture set. Never copy one branch's output digests or source revision onto another.

## Verification and publication

1. Build the final candidate twice independently on hosted runners at the same integration revision. Capture actual image IDs, complete normalized filesystem/config digests, final native dependency closure, tool/probe hashes, raw Syft, Grype and database receipts. Reconcile named, versioned OS and NuGet inventory against vendor manifests and the final image. Verify MessagePack 2.5.307 and the disposition of former Wolfi glibc, libexpat and MessagePack findings. Repeat a known-vulnerable positive control for the actual distro feed.
2. Map all 13 old #74 rows, every baseline #75 row, all 20 #76 rows, and every new finding by CVE/alias, binary/source package, PURL, version and fix state. Check Ubuntu advisories independently, including vendor-affected releases missing from Grype. Keep duplicate PURLs visible. Document signed version evidence for fixes and inventory/file evidence for removals. An unknown, ambiguous identity, raw/vendor disagreement or unsupported severity stays open. A zero scanner count alone cannot qualify an image.
3. For residual issues, first test supported fixes or removal of an unused affected component with dependency and behavior proof. Present each remaining policy-eligible finding with exact scope, owner, rationale, controls, expiry and proposed protected ledger binding. No automatic transfer of the historical Kiota exception. Defer retiring that obsolete row until the new candidate's complete disposition is known. Prepare a separate owner decision for an exact protected-main ledger change if needed. [Ledger retirement conditions](u1-r15-kiota-138-ledger-retirement-proposal-2026-11-17.md)
4. Run Kiota offline as UID/GID 65532 with the existing read-only, CPU/memory, process and time limits. Exercise .NET runtime discovery, globalization and summer/winter Jerusalem offsets. For each branch compare two clean bounded runs of all three generated consumers against its own previous source baseline. Verify every output path/digest, inspect semantic differences, compile the .NET client and exercise request serialization and response deserialization. Rerun the pinned C01–C27 package, immutable-base compatibility, lint, types, unit and integration suites and the 80% line coverage gate.
5. Review the exact recipe and pin set, the generated diffs and the two raw evidence sets before story pushes. Preserve all three PRs' own histories. Verify each final PR's current base/head/test-merge again. Obtain fresh exact-head U2 owner comments for changed heads, rerun U2, and collect ordinary U1 and vulnerability jobs on **each** final revision. Repeat the independent runtime comparison on the final integrated tree if publication changes it. Retain SBOM/scan artifact IDs and hashes, successful protected-ledger receipt, combined SBOM digest and authorized attestation when available. Update NFR13.2, NFR13.5 and NFR15.2 against that evidence. Keep R-15 open whenever an applicable job, required disposition or governed artifact remains unresolved.

The investigation can produce a technically verified candidate while protected-main disposition or attestation still awaits an owner decision. This plan covers working-branch remediation. U1 acceptance and C01 release remain separate decisions.
