Status: proposed, awaiting a new protected plan approval. This is an implementation plan, not vulnerability acceptance, merge authority, U1 acceptance or C01 release. The earlier patched Noble approval remains historical authority for its completed runtime work.

## Problem and scope

PRs #74–#76 currently share base 402ace3b195c291a756ed230a24a73199ef8349a and runtime sha256:1c7fc5fd4df187a3571460bf807e860f1be6bfd704c3fd9fe037c641adea5340 but have different execution fingerprints. U1 rejects main's obsolete v1 ledger. The current verifier also rejects multiple v2 baselines, and PR74 cannot consume a v2 SBOM receipt. The SBOM consumer currently checks execution/runtime digest syntax without independently comparing those fields. These are the specific defects this plan repairs.

Implementation is limited to the three U1 working branches and a focused shared prerequisite branch if useful; preserve each story and unrelated changes. Primary files are tools/contracts/src/image-ledger.mjs, src/sbom.mjs, scripts/build-sbom.mjs, existing candidate/execution and runtime-evidence helpers, all production SBOM call sites requiring independent context, their tests, explicit test script lists where necessary, and traceability/source-manifest additions. No runtime, dependency, scanner policy, U2 policy or branch-protection change is included. Record every current branch head before edits and inspect staged changes before commits/pushes.

## Implementation

1. Keep v1 semantics unchanged. Validate the entire v2 ledger before selecting by exact (executionFingerprint, runtimeManifestDigest). Reject malformed or expired rows even in unrelated groups, duplicate findings within a group, invalid images/identities/PURLs, unknown severity or fix state, and missing owner, rationale, controls, approval reference or active validity times. Permit the same finding once in each separately approved baseline. Select only the exact pair; a nonempty ledger with no matching group fails. Preserve empty-ledger clean-image handling. Selected findings must match current raw scans exactly, with no extras, omissions or fixed High/Critical exceptions; compare disposed totals to the selected group.
2. Preserve exact source revision, Git tree, candidate digest, actual image/SBOM/raw-scan binding, complete runtime manifest, immutable protected-main blob and live-main recheck. Keep only the existing ledger-file exclusion needed to avoid circular binding; never exclude verifier/tests/policy paths. Do not trust a PR-supplied ledger, runtime-only approval, branch name or PR number.
3. Bring the existing v2 receipt support to PR74 without overwriting US8.2 changes. Strengthen v2 SBOM consumption on all three branches. Derive expected HEAD, tree SHA and recursive Git tree using bounded shell:false Git calls and the existing canonical candidate/execution digest functions. Require candidateRevision to equal actual HEAD and reject dirty protected execution paths. Pass independently derived expected values to the SBOM builder; compare receipt candidate tree SHA, candidate digest and execution fingerprint by equality. Never take expected digests from the receipt or caller environment. Audit every production buildSbom call site and supply independently derived context consistently; missing context fails for v2.
4. Recompute runtime evidence using readKiotaRuntimeEvidence against the verified Kiota image ID and retained image SBOM, then compare its normalized digest to the receipt. This validates retained manifest/config bytes and image binding without relying on the receipt's digest as its own authority. Preserve exact receipt fields and source/image scan checks. Existing v1 consumers remain supported.
5. Independently review the change, run the checks below, and publish only reviewed working-branch changes after technical checks pass. Recompute final heads, test merges and execution fingerprints. Refresh exact-head owner U2 comments through the owner; never fabricate comments. Follow all applicable hosted jobs and record each failure honestly.
