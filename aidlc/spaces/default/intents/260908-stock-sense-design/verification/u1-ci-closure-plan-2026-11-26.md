## Scope and explicit policy decision

This amendment supersedes the earlier prohibition on non-main ledger authority only for the temporary, explicitly selected PR mode described below. It also authorizes bounded runtime remediation for the two contract-tool images, subject to exact candidate review and the stop points below. It preserves Node 24.22.3 binary provenance, all package/tool pins unless an explicit candidate amendment is reviewed, raw scan completeness, unknown and fixed High/Critical refusal, whole-ledger validation, independent SBOM binding, unprivileged public-PR execution and required-check enforcement.

The owner is being asked to permit reviewed candidate code to interpret a separate owner-authenticated immutable-ledger authorization, after an independently sourced U2 job approves that exact candidate. This is not a semantic ledger verifier already deployed on protected main. The distinction is a material trust-policy choice and must appear in the approval question. If the owner requires the new ledger semantics themselves to run from pre-existing protected-main code, stop: the green-before-merge bootstrap is not supported by this plan.

No protected-main modification/publication, U2 workflow or enforcement change, required-check waiver, risk exception, force-push, merge, cloud resource, deployment, U1 acceptance or C01 release is included. Main push and release remain protected-main-only. This plan does not automatically authorize the later main migration or extension to another PR/base.

## Temporary PR authority contract

Use a distinct authority tag `owner-authorized-pr-ledger-v1`; retain `protected-main` for existing main authority. Explicit PR mode is eligible only for open same-repository `pull_request` events in `anton-asnitsky/StockSense`, numeric repository and owner IDs obtained from authenticated GitHub metadata, PR numbers 74, 75 or 76, target branch `bolt/u1-candidate-ready` at exact base `402ace3b195c291a756ed230a24a73199ef8349a`. A base move is not automatically admitted: review the changed baseline and amend this allowlist before requesting authority. No fork, arbitrary PR, push, workflow_dispatch, main push or release context is eligible.

Use the fixed ledger path `security/image-exceptions.json` at an immutable same-repository ledger commit; reject non-blob modes, traversal, symlinks, wrong object identity and decoded payloads larger than 1 MiB. Verify Git blob SHA and SHA-256 of exact bytes; do not trust branch names or candidate-reported hashes. Bound JSON depth/structure using the existing closed ledger schema and validate every row before selection. An empty ledger is permitted only for actually clean bound scans. Ledger commits may live on an isolated working branch and are evidence-only; they are not main publication.

The owner must post one exact, separate, GitHub-authenticated authorization body per candidate. The final parser uses one canonical field order and exact lowercase digest formats, rejecting extra/missing/duplicate fields or prose. Proposed grammar:

```text
StockSense PR ledger authority v1: repository=<numeric-id> pr=<number> base=<40hex> head=<40hex> candidate=<sha256:64hex> execution=<sha256:64hex> runtime=<sha256:64hex> ledgerCommit=<40hex> ledgerBlob=<40hex> ledgerSha256=<sha256:64hex> policyCommit=<40hex> expires=<YYYY-MM-DDTHH:mm:ssZ>
```

`policyCommit` identifies the exact reviewed candidate head containing the PR authority implementation; it must equal `head`. Separately record the independently sourced U2 policy commit in the receipt. This avoids confusing candidate policy with pre-existing trusted policy. `runtime` retains the reviewed normalized Kiota runtime binding; both actual image IDs and complete validator/Kiota inventories/scans remain separately mandatory. `candidate` and `execution` are independently recomputed using the current production definitions, never copied from the comment.

Require repository owner numeric ID plus exact owner login, User type and OWNER association. The comment must belong to that PR, have identical `created_at`/`updated_at` (edited comments are rejected), and be retrievable by ID during final validation. Lifetime is at most seven days from its GitHub `created_at`, and its expiry must not exceed the absolute eligibility sunset **2026-12-10T23:59:59Z**. No clock grace past expiry; test with an injected clock and use the actual hosted clock in production. Renewals need a new genuine comment and cannot extend the sunset without a new protected plan.

List every comment page to completion with a hard bound of 100 pages of 100 comments; exceeding the bound, rate limiting, permission failures, missing metadata or incomplete pagination fails closed. Require exactly one unexpired matching authorization; even identical duplicate applicable comments fail until the owner removes the duplicate. Reject conflicting applicable payloads. Retain comment ID, exact body hash, creation/update times, owner/repository IDs, expiry and retrieval times. Re-fetch PR, owner comment and independent U2 evidence immediately before receipt issuance and reject any change. Deleted/edited/revoked authorization cannot be revived by a retained receipt; the owner revokes by deleting the comment, closing the PR or moving its revision. Each run validates live authority afresh. Preserve current main commit/blob as contextual evidence without claiming main endorsed PR ledger bytes.

Receipt schema must distinguish authority types explicitly and bind source/test-merge commit and verified parent order, target base/head, candidate/execution/runtime, immutable ledger bytes, all scans/images/SBOMs and U2 provenance. A copied PR receipt is not authority for another candidate or later run and must never pass main/release verification. The entire trust implementation stays in read-only-token unprivileged PR execution; no secret or privileged checkout is introduced.

## Stop points and owner decisions

1. Before implementation: independent plan reviews, explicit protected Plan Approval and verified current receipt.
2. Before runtime rollout: independent exact-digest candidate review; return for scope amendment if remediation requires a different distribution/libc/tool/dependency strategy or leaves unknown findings.
3. Before ledger use: separately approved current finding decisions where policy permits, followed by distinct exact-byte publication authorization. Plan approval is neither decision.
4. Before claiming green: genuine final U2 comments, successful independently bound U2 results, all nine ordinary checks successful and unchanged revisions/live authority.
5. After green: stop for owner merges. Main compatibility/ledger publication, temporary-mode removal or any sunset extension, U1 acceptance and C01 release remain separate reviewed work.
